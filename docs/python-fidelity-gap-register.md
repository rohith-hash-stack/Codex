# Python Index Fidelity — Gap Register

**Version:** 6
**Baseline:** `main`@`98fb59ca7d1ddf732523fcadfca15df6b4863b2f` (superseded by `8adaa5d` after GAP-11's fix merge, then `463a582` after GAP-12's, then `ba820af` after GAP-13's, then `09388b6` after GAP-14's, then `dbc9fce` after FND-1's)
**Scope:** the SCIP provider's Python-language fidelity (`codex.provider.scip*`), plus its AST-provider counterpart (`codex.provider.ast_calls_adapter`) where they overlap. Indexer: `scip-python@0.6.6` (`docs/resources.md`).
**Method:** raw wire-format inventory against 5 real repositories (django, flask, click, pytest, requests), traced through decode → normalize → identity → graph → candidate → retrieval, per the acceptance-gate discipline in the Phase-2 directive.

This register is the single source of truth for Python-specific fidelity gaps. Every row must reach `FIXED + REGRESSION-LOCKED` or `ACCEPTED — outside contract` with explicit evidence before Python 100% may be declared. No row may remain `UNKNOWN`.

**Version 5 update:** GAP-14 is now FIXED / MERGED / REGRESSION-LOCKED (see row below) — the sole gap the post-GAP-13 exhaustive audit found blocking Python 100%. **Methodology correction, disclosed here in full:** that audit's own headline count of "53 confirmed splits" was itself measured with a crude candidate-matching heuristic (fuzzy name substring matching against the whole graph) that produced false positives whenever a common short name (e.g. `subject`, `case_sensitive`) coincidentally matched an unrelated entity elsewhere in a large repository. This fix cycle's own validation replaced that heuristic with an exact file+enclosing-scope+name cross-provider match and found the real, rigorously-confirmed pre-fix count was **9** splits (django 2, click 3, pytest 3, requests 1, flask 0) — all 9 are fixed by this cycle, with zero new splits and zero incorrect merges introduced anywhere across all 5 repositories. The other ~38 of the original ~53 were, on precise re-examination, cases where `AstCallsAdapter` never independently produces a counterpart entity at all (bare class-attribute assignments, locally-nested-class attributes, and similar shapes its own `_DefinitionCollector` does not track) — there is no second identity to converge with, so these were never AST/SCIP splits in the first place, matching the same "no AST counterpart" category the original GAP-13 audit already established for flask's `static_folder`/`max_content_length`. The Python 100% gate remains **NOT MET**: per the standing instruction under which GAP-14 was fixed, closing it does not by itself permit declaring Python 100% — a fresh exhaustive Python fidelity audit must still be run against this new merged baseline (`09388b6`), and that re-audit has not yet been performed.

**Version 6 update:** FND-1 is now FIXED / MERGED / REGRESSION-LOCKED (see row below, moved out of "Newly discovered, not yet fixed") — the one remaining, previously-out-of-scope finding this register carried since GAP-13's cycle. **A second, dedicated round of validation inside this same fix cycle found and corrected a real false-negative in the fix's own first design**, disclosed here in full rather than smoothed over: the initial detection (matching each ambiguous occurrence to its nearest textually-preceding real symbol definition at a shallower *SCIP occurrence column*) passed 169/170 real cases across all 5 repositories, but its one exhaustive-sweep mismatch — django's `Signal.asend` — traced to a structural flaw, not a fluke: `def send(...)` and `async def asend(...)` are genuine top-level siblings at identical true indentation, but `async def`'s extra 6 characters shift `asend`'s identifier column enough that a raw-column comparison misread `send` as `asend`'s enclosing container. The fix was corrected to compare true source *indentation*, read directly from the repository's own source file on disk, falling back to the original column comparison only when no real source file is available (every handcrafted test fixture predating this correction, and the rare case of a `.scip` index whose source tree has since moved). Re-running the exhaustive sweep after this correction found **zero mismatches** across all 5 repositories: 164/164 genuinely-distinct symbols verified, 515 total correctly-split entities (django 393, flask 19, click 3, pytest 100, requests 0). The Python 100% gate remains **NOT MET**: per the standing instruction under which this cycle was scoped, fixing FND-1 does not by itself permit declaring Python 100% — a fresh, exhaustive Python fidelity audit must still be run against this new merged baseline (`dbc9fce`), and that re-audit has not yet been performed.
