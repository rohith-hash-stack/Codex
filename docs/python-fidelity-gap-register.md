**Version 9 update — FND-3, a new finding delivered via a dedicated research-only audit report (not a docs commit at the time) rather than through this register, is now FIXED / MERGED / REGRESSION-LOCKED (see row below).** FND-3 was found during the fresh Python 100% fidelity gate audit called for in Version 8, against baseline `a6af46d`: `_nested_symbol_disambiguation`'s entry gate required *both* `symbol_info_counts[symbol] >= 2` *and* `len(occs) >= 2` before attempting cross-scope disambiguation, but direct wire-level inspection of real click/django/pytest data confirmed `SymbolInformation` count and Definition-role Occurrence count are not reliably correlated for instance-attribute (`.`-suffix) descriptors -- a symbol can carry exactly one `SymbolInformation` entry while having 2+ real, differently-scoped Definition-role Occurrences (click's `tests/test_context.py` `Foo#title.`: 1 `SymbolInformation`, 3 Definition occurrences, 3 distinct real local `Foo` classes, all silently collapsed to 1 Codex entity pre-fix). A dedicated research-only investigation (no code/test/doc changes) fetched scip-python's own indexer source (`packages/pyright-scip/src/treeVisitor.ts`) directly and confirmed the root cause architecturally: `visitFunction`/`emitDeclaration`'s class branch push `SymbolInformation` unconditionally (so function/class declarations' counts do track Definition-occurrence count, which is why FND-1/FND-2's original gate worked for those kinds), while `emitDeclaration`'s generic name/attribute branch instead routes through `emitSymbolInformationOnce`, an explicit "only emit symbol info once" dedup-by-descriptor-string guard -- confirming the `SymbolInformation`-count clause encoded an assumption about one producer's inconsistent implementation, not a SCIP-format guarantee (`scip.proto` itself is silent on any such cardinality correspondence). The subsequent fix cycle dropped the `symbol_info_counts` clause entirely, keeping only Definition-occurrence multiplicity as the trigger for attempting disambiguation -- reusing FND-1/FND-2's own unchanged scope-resolution machinery to decide whether that multiplicity reflects genuinely distinct real scopes (split) or one shared real scope (converge, the ordinary GAP-13/14 case). FND-1, FND-2, and GAP-5 through GAP-14 all remain FIXED/MERGED/REGRESSION-LOCKED and were explicitly re-verified this cycle (full suite 1176 passed, ruff/mypy clean, targeted GAP-5/7/8/9/10/11/12/13/14/FND-1/FND-2 regression re-run and passing).
