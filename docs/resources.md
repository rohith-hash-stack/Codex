## Two material findings from this pass

1. **CodeQL's licensing is not permissive for arbitrary repositories.** Free use is scoped to public/open-source analysis or academic research; private-repo analysis requires a commercial GHAS license. This is now a concrete input to ADR-005 and to how the Capability Registry should represent CodeQL's availability per-repository, not just per-installation.
2. **`SillySerpent/Repograph` is AGPL-3.0.** Codex's existing "reuse the idea, not the code" stance toward that project (recorded in `docs/research/provider-formats.md` and `docs/architecture-conformance-audit.md`) turns out to be a license requirement, not just a caution — vendoring or wrapping that code would obligate Codex to AGPL-3.0 terms.

Neither finding blocks the next implementation steps (`ProviderAdapter` contract, Capability Registry, Git Adapter, ingestion pipeline, SCIP Adapter) — both matter once ADR-005 and ADR-006 are actually drafted.

## Third material finding — D7 (2026-08-31)

3. **All three candidate "at least one repository intelligence provider" sources (HLRD §8) have a real, blocking problem, not a preference-level one.** `SillySerpent/Repograph` is AGPL-3.0 *and* exposes no portable artifact (CLI/Python-API/MCP over an in-process Kuzu store only) — there is nothing safe to consume without either violating the license or reimplementing its entire pipeline. `chokevin/repograph` is MIT (no license obstacle) but its one capability Codex doesn't already have from Git+SCIP+CodeQL — `calls`/`references`/`inherits` edges — is built by a sub-2-second tree-sitter pipeline with no documented type/semantic resolution, the same shallow-syntax profile D5's own research already showed is insufficient to deterministically distinguish a call from a bare reference; adopting it would mean putting an undemonstrated-determinism relationship into the canonical graph. **Sourcegraph** remains genuinely un-researchable from this environment (`sourcegraph.com` still returns a connection failure, not just a slow response) and would in any case require either a live external API dependency or a full self-hosted deployment — a materially different, heavier input-contract shape than every adapter built so far. This blocks D7 as a genuine architectural gate (`docs/architecture-conformance-audit.md`'s §K) rather than an implementation detail to route around.
